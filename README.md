# GNSS 信号监测台架

一块 2.4 英寸的触摸屏，实时告诉你天上的卫星信号**现在到底可不可信**。

不是"能定位就行"的 GPS 模块演示 —— 它算的是误差上界、盯着慢漂移、识别多径，
并把每一次判定变化写进掉电不丢的日志里。

> 硬件是现成的模块，软件是这台台架的全部价值。

---

## 1. 它解决什么问题

普通 GNSS 模块只输出两样东西：坐标，和"我定位成功了"。

但在实际使用中，**"定位成功"和"定位可信"是两件事**。冷启动首解、半边天被楼挡、
窗边玻璃反射，都能给出一个 `fix=1` 却偏出几百米的解 —— 而下游系统完全不知道自己被喂了错数据。

这台台架做的事：把"可信度"变成屏幕上一眼能懂的一个词 + 一组可追溯的数字。

| 屏上看到 | 含义 |
|---|---|
| `INTEG-OK`（绿） | 解在误差上界之内，可用 |
| `DRIFT`（琥珀） | 解没越线，但偏移在缓慢单调增长 —— 疑似基准过期 |
| `HPL-HIGH`（紫） | 误差上界本身太大（星少 / 信号弱），此刻的"精度"没有意义 |
| `POS-BAD`（红） | 偏移当场越过门限，这是已经发生的事实 |
| `SIG-BAD` / `LOST` | 信号或定位已丢失 |

## 2. 两块板

```
        天空
          │  NMEA (UART)
          ▼
   ┌──────────────┐        UART 交叉线        ┌──────────────┐
   │  ESP32-S3    │◄────── 协议 P2 ─────────►│  ESP32-C3    │
   │  台架面板     │   心跳 / 回执 / 事件搬运    │  手持命令板   │
   │  2.4" 触摸屏  │                          │  2.4" 触摸屏  │
   │  GNSS + 温湿度│                          │  菜单 + 软键盘│
   └──────────────┘                          └──────────────┘
```

**S3 = 台架面板。** 接 GNSS 模块与温湿度传感器，跑全部算法与界面。
它是"在地面看一眼"的那一端，装在三米杆子上时人够不着。

**C3 = 手持命令板。** 一根 UART 线接过去，人在地面就能设基准、查状态、翻事件、
配 WiFi。它的屏幕和 S3 一样大，但只做菜单和输入 —— 键盘输入在下面敲，比在杆子上够着按可靠得多。

两板之间有心跳（`ping`/`pong`），链路断了 C3 会自己显示出来，不会让你对着一个死菜单按。

## 4. 三个算法

全部在 S3 上以 1 Hz 实时跑，屏上能看见中间量 —— 不是跑完只给你一个结论。

### 4.1 误差上界（HPL）

```
HPL = 5.33 × HDOP × σ_UERE
σ_UERE 由 C/N0 反推：σ = 0.6 m @ 45 dB-Hz，按信号强度衰减
```

`5.33` 是水平/垂直误差比与完好性风险乘子合成后的常数。HPL 回答的是
**"我敢保证的误差圈有多大"** —— 偏移没超它，就不该报异常。

> 取 σ 时按 C/N0 取最强的前 N 颗。**不要用 GSA 的 PRN 槽位** ——
> 多句 `$GNGSA`、句名一律 `GN`、PRN 跨星座重号，照它配会产生 σ≈8.7 m、
> HPL 常年 40 m 的假警报（本项目实测过）。

### 4.2 慢漂移（CUSUM）

偏移的突变好抓，**慢漂移难抓**：0.05 m/s 的斜坡，10 分钟就走 30 m，而每一拍看起来都很正常。

用累积和：`S += (dev − k)`，`S` 超门限即报警。
- μ = 慢基线（τ ≈ 5.5 min），不是当前值
- 统计量有 8 m 绝对闸，防止"基线跟着漂"
- **前 90 s 只建 μ，统计量锁 0** —— 冷启动那一拍的数据不可信，
  拿它当基线会让设备"一开机就在漂"

> 实测结论（与此前的设计直觉不同）：在 0.02~0.4 m/s 的斜坡下，
> **8 m 绝对闸先到，CUSUM 再确认**。所以这里的 CUSUM 是第二道闸，
> 不是提前量。`tools/cusum_replay.py` 可以离线复现这张表。

### 4.3 多径识别

按卫星仰角建 C/N0 模板，实际值低于模板超过阈值即判为多径。
用递推最小二乘（RLS）在线更新模板系数，忘记因子让模板能跟着季节和树冠变化。

## 5. 界面

主界面（星空粒子背景 + 四角现场量 + 数据条）：

```
┌──────────────────────────────┐
│ 卫星数/总数      HDOP          │
│                              │
│      ·  ·   ·                │
│   ·   ·  ·    ·   ← 星空      │
│  ·   ·   ·  ·                │
│                              │
│ 经纬度            温度/湿度    │
├──────────────────────────────┤
│ INTEG-OK   OFF 12.4m  HPL 15m│
│            CN0 31   SAT 16/26│
├──────────────────────────────┤
│  CHARTS  │  LOG  │  TUNE  │  │
└──────────────────────────────┘
```

- **长按数据条 900 ms** → 底部换成 8 行原始 NMEA 报文
- **长按 CHARTS 1.5 s** → 参数页（8 项阈值可调，掉电保存）
- **按 BASE 键** → 采 10 s 平均设基准（有两道准入闸，见下）
- **主界面右上角** → WiFi 卡片，显示 IP
- 六个页面：主界面 / 图表 / 日志 / 事件 / 参数 / 参数编辑

图表页四张卡：柱状星况、误差趋势、完好性、检测器 —— 每张都在动，说明它真的在算。

## 6. 一个踩过的坑（值得单独说）

**按 BASE 设的基准会被永久写进 flash，之后每次开机都拿它当尺子。**

老版本的准入条件只有 `fixValid` —— 但"有定位"不等于"定位准"。
冷启动首解、墙边多径都能给出 `fix=true` 却偏 200 m 的解，按一下就把坏尺子焊死了，
表现像"设备永久漂移 200 米，重启也甩不掉"。

现在的两道闸：

```
P1 质量门限：fixValid + 卫星 ≥ 6 + HDOP ≤ 2.0 + 定位新鲜 < 3 s
P2 采样平均：再 1 Hz 采 10 s，样本 ≥ 8 且极差 ≤ 25 m，才写均值
```

**凡是会被写进 flash 的参考量，入口的准入条件就是它的精度上限。**
只校验"有没有"、不校验"准不准"，等于把随机误差永久固化，而且症状会长得像别的部件坏了。

界面上同时显示 `base set` 与 `base new`：前者是旧基准，后者是刚设的。
`off 266 m` 时，你得能分辨是"尺子过期"还是"设备真坏了" —— 这两种处置完全相反。

## 7. 编译与烧录

### 7.1 依赖

- Arduino ESP32 core **3.3.8**
- **TFT_eSPI 2.5.43**

TFT_eSPI 的引脚配置不在本仓库里生效，必须把 `hardware/` 下的两个头文件
分别拷到库目录：

```
<Arduino>/libraries/TFT_eSPI/User_Setup_GNSS_Bench.h   ← 用于 S3
<Arduino>/libraries/TFT_eSPI/User_Setup_C3_CmdPad.h    ← 用于 C3
```

改完把 `TFT_eSPI/User_Setup_Select.h` 里的 `#include` 指到对应那个。
**这一层最容易出"编译通过、屏上一个像素不画"** —— 缺字库时不会报错、不会崩，
只是什么都不显示。

### 7.2 命令行

```bash
# S3
arduino-cli compile --fqbn "esp32:esp32:esp32s3:CDCOnBoot=cdc,PSRAM=opi,FlashSize=16M,PartitionScheme=custom" \
  --build-path "$TEMP/gnss-build" --output-dir "$TEMP/gnss-out" firmware/GNSS_Bench

# C3
arduino-cli compile --fqbn "esp32:esp32:esp32c3" \
  --build-path "$TEMP/c3-build" --output-dir "$TEMP/c3-out" firmware/C3_CmdPad
```

> **`--build-path` 绝对不能指向同步盘 / OneDrive。** 缓存文件在同步过程中被改写，
> 链接阶段会报一大片 `undefined reference`，连 `millis` 都找不到。

### 7.3 不编译，直接烧

`firmware/prebuilt/` 下有两块板当前版本的 bin。S3 只需烧 app（0x10000），
校准、WiFi 台账、事件日志、基准全部保留：

```bash
esptool.py --chip esp32s3 --port COM4 write_flash 0x10000 firmware/prebuilt/S3/GNSS_Bench.ino.bin
```

C3 是整片烧（首次换板必须整片烧，否则 NVS 里的旧数据会打架）。
详细的地址表见 [`docs/台架搭建.md`](docs/台架搭建.md)。

## 8. 串口

电脑 USB 接 S3，115200。敲 `?` 打印全部命令（17 条）。

C3 通过 UART 链路能远程触发的只有**单键白名单**里的 8 个 ——
这是刻意的安全边界：能从杆子下面触发的能力，必须是"看了就知道会怎样"的那几个。

## 9. 已知限制（诚实清单）

- **移动端未验证**：所有判据在固定台架上调过，没有做过动态场景
- **多径判据未与真值对比**：只做了"阈值会响"，没有标注数据集算准确率
- **CUSUM 不是提前量**（见 4.2），别指望它比阈值法更早发现
- **不适合做欺骗检测**：单频单星座，无法区分"信号被伪造"与"多径严重"
- 界面为 240×320 定制，换屏要重排全部布局
