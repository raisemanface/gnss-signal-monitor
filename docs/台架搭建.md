| **报文在滚** | 屏中部 | 最近几句 NMEA 原样滚动(自动折行,句子看全),未经任何加工。**点这个区进"动图页"** |
| **log 在长** | 屏底计数行 | **`r/s`** 每秒 8~12 行地在跳、**`par`** 顶着 100.0%,证明不是静态截图(2026-10-01 起已不是 `lines`/`parsed` 两个绝对计数) |
| **温湿度在跳** | 屏右下角 | `T 25.3C` / `RH 48%`,2 秒刷新一次。晶振频率会随温度漂,机箱内的环境本身也是要记的一项 |

> 灯用开发板**自带的 WS2812 彩色灯**,一个件都不用焊,与屏上色带同步 —— 远处看灯,近处看屏。
>
> ⚠ **先纠正一个常见说法:「板载」不等于「不占 IO」。** 这颗灯是 WS2812 单总线可寻址灯,
> 数据线必须挂到一个脚上 —— 通常是 **GPIO48**(官方 DevKitC-1 **v1.1** 是 48,**v1.0** 是 38;
> 国产 N16R8 / 克隆板常见 48,也有 38 / 21 / 47)。它是**占掉一个 GPIO** 的,只是不用外接线。
>
> 好消息是:你台架的脚位表(**16/17/18** GNSS、4/6/10/11/12/13 屏、9/5 触摸、7/8 I2C)里没有 48,
> 所以这个脚本来就闲着 —— 对你来说等于白捡一颗状态灯。
>
> 另外:**有些板子的 RGB 数据线出厂是断开的**,灯旁边有一对丝印为 `RGB` 的小焊盘,
> 要用锡短接之后灯才会连到 GPIO48。没短接的表现很坑:程序烧录正常、屏也正常,**就是灯不亮**。
> 不确定灯挂在哪就烧进去,串口发 `l` 让它挨个试。

## 三、接线表

### GNSS 模块 → 主控

| ESP32-S3 | 接到 | 说明 |
|---|---|---|
| **GPIO16** (RX1) | 模块 TXD | 数据入 |
| **GPIO17** (TX1) | 模块 RXD | 可选,只收不发可以不接 |
| **GPIO18** | 模块 PPS | 1Hz 秒脉冲输入(观测/驯服用,串口 `g` 查看) |
| 3V3 | 模块 VCC | **模块没带 LDO 时必须 3.3V**,接 5V 会烧 |
| GND | 模块 GND | 共地,别忘 |

> ⚠️ **引脚已调整(2026-09-30 接真模块)**:原来是 `GPIO18=TXD / GPIO17=RXD`,因为 18 要让给 PPS,
> 已改为 **16=TXD / 17=RXD / 18=PPS**。固件里有 `static_assert` 守着 PPS 不与 I2C(7/8) 撞脚。

### 屏 → 主控(SPI)

> 引脚**照抄已交付项目 `RF_Source_Controller` 的实测接线,不是猜的**(同一块屏、同一块 S3)。
> 它固化在 `User_Setup_GNSS_Bench.h` 里,固件配置区有同名常量,两处对不上会**编译报错**,不用烧进去试。

| ESP32-S3 | 屏脚 | 说明 |
|---|---|---|
| GPIO12 | SCLK / T_CLK | SPI 时钟 |
| GPIO11 | MOSI / T_DIN | 主发 |
| **GPIO13** | **MISO / T_DO** | **触摸要用这条回线,必须接** |
| GPIO10 | CS | 屏片选 |
| GPIO6 | DC | 数据 / 命令 |
| GPIO4 | RES | 屏复位 |
| — | BLK / LED | **背光直接接 3V3,常亮**。⚠ 本项目就是这么接的,所以 **GPIO7 是空着的** —— 给下面 SHT30 当 SCL 了 |
| GPIO9 | T_CS | 触摸片选 |
| GPIO5 | T_IRQ | 触摸中断(轮询方式可不接) |
| 3V3 | VCC | |
| GND | GND | |

没有外接 LED、没有按钮 —— 整台机器就十来根杜邦线加一块屏。

> ⚠️ **BLK 一定要接。** 早先有一版配置漏了背光,现象是"上电后屏全黑",极容易误判成固件没烧进去或者屏坏了 —— 实际是背光没供电。
>
> **本项目实测:BLK 直接接 3V3**,常亮、不占 IO,背光也就**不受代码控制**(用不着"记得拉高")。
> 上表里的 GPIO7 是从 `RF_Source_Controller` 沿用的 —— **那边**背光走 GPIO7,本项目 GPIO7 是空的,给了 SHT30。
> 万一你的屏 BLK 其实插在 GPIO7 上:那就把配置区 `TFT_BL_ON_GPIO` 改成 `1`(背光才受控),但**那样 GPIO7 就不能再给 I2C**,SHT30 的 SCL 得挪到 GPIO15。

### SHT30-D 温湿度 → 主控(I2C)

| ESP32-S3 | 接到 | 说明 |
|---|---|---|
| GPIO7 | SHT30 **SCL** | 这一脚本是背光控制脚;本项目背光接 3V3,所以空着 |
| GPIO8 | SHT30 **SDA** | |
| 3V3 | SHT30 VCC | SHT30 是 3.3V 器件,别接 5V |
| GND | SHT30 GND | 共地 |

> 驱动走 ESP32 核心自带的 `Wire`,**不用装任何库**。
> 模块一般已带 4.7k 上拉;若是裸芯片,SDA/SCL 各要一只 4.7k 上拉到 3V3。
> 地址默认 `0x44`(ADDR 接地),固件找不到会自动再试 `0x45`。串口发 `t` 可立刻验证通不通。

## 四、软件环境

> ## ⚠️ 先看这一条:这台电脑上有**两个** ESP32 内核,IDE 里名字一模一样
>
> 两个内核在开发板菜单里都显示 `ESP32 Arduino`,**从名字上完全分不出来**:
>
> | 包 | 版本 | 状态 |
> |---|---|---|
> | `esp32:esp32`(Espressif 官方) | 3.3.8 | **完好** ← 选这个 |
> | `arduino:esp32`(Arduino 那份) | 3.3.7 | **残缺**:`tools/` 下缺 `esptool`、`esp32-arduino-libs`,选中它会编译到最后一步报 `系统找不到指定的路径 / exit status 1` |
>
> **怎么确认自己选对了**:编译完看输出区的 `FQBN:` 那一行 ——
> 必须是 `esp32:esp32:esp32s3`。如果是 `arduino:esp32:esp32s3`,就是选错了那个残缺包。

1. Arduino IDE 装 ESP32 支持,开发板选 **ESP32S3 Dev Module**(Espressif 包下的那个)
2. 库管理器装 **TFT_eSPI**(by Bodmer)—— **整个工程只需要这一个库**
3. **板载彩灯不用装库。** 它走 Arduino-ESP32 核心自带的驱动函数:
   - 核心 **3.x** → `rgbLedWrite(pin, r, g, b)`(官方推荐名)
   - 核心 **2.x** → `neopixelWrite(pin, r, g, b)`(同一功能,旧名;在 3.x 里仍保留,只是标了 deprecated)
   代码里两条都写好了,按 `ESP_ARDUINO_VERSION_MAJOR` 自动选,不用你管。
   (万一你想改用 Adafruit NeoPixel,把文件顶部 `LED_USE_BUILTIN` 改成 0,再装库即可。)
4. **「工具」菜单里必须设的两个选项**:
   - **USB CDC On Boot → `Enabled`** ← **这条不设,串口监视器会一片空白**
     你这块板子的数据线插在**原生 USB 口**(Windows 里 VID `303A:1001`,即 USB-Serial-JTAG)。
     而 `USB CDC On Boot` 默认是 `Disabled`,此时 `Serial` 走的是 **UART0(GPIO43/44)** ——
     那个口在原生 USB 口上什么都没接,所以你什么都看不到,会误以为"固件没烧进去"。
     设成 `Enabled` 后 `Serial` 才映射到 USB CDC。
     *(反过来说:哪天你换用板载 CH340 那个 UART 口,就要把它设回 `Disabled`。)*
   - **Flash Size** 按你板子的实际容量选(不确定就留默认 `4MB` —— 这个程序才占 30%,够用)
5. **挂屏配置** —— 这一步不做,屏不亮也不亮触摸:
   - **最省事**:把项目根目录的 `User_Setup_GNSS_Bench.h` 复制过去**覆盖**
     `<库目录>/TFT_eSPI/User_Setup.h`。`User_Setup_Select.h` 开头默认就是
     `#include <User_Setup.h>`,覆盖它即可生效,不用再改别的文件。
   - 想保留原文件,才走 `User_Setups/` + 改 `User_Setup_Select.h` 那条路(文件头注释里有)。
   - ⚠️ **该文件已按"本机实测生效"逐行核对齐**,其中三条宏缺一不可:
     `TFT_RGB_ORDER TFT_BGR`(缺了蓝红反色)、`USE_FSPI_PORT`(S3 + 核 3.x 必须)、
     `XPT2046_Touchscreen`(触摸支持)。旧副本漏了这三条,别再用旧版。
   - 挂错不要紧:固件里有**编译期自检**,会直接报
     `当前生效的 User_Setup 引脚不是台架接线` 并列出应有的脚号 —— 一眼看出没挂对。

### 命令行编译/烧录(现在的主力方式)

菜单里两个内核同名,选不准就敲命令。**本机当前用的 arduino-cli 在 WorkBuddy 的二进制目录下**(配了一份 `arduino-cli.yaml` 指向本机已有的 esp32 核和库):

```bash
CLI="/c/Users/<you>/.workbuddy/binaries/arduino-cli/arduino-cli.exe"
SRC="~/gnss-signal-monitor/firmware/GNSS_Bench"
CACHE="/c/Users/<you>/AppData/Local/Temp/gnss-cache"   # ★ 中间缓存 —— 必须本地盘!
OUT="/c/Users/<you>/AppData/Local/Temp/gnss-build"     # ★ 导出产物 —— 必须本地盘!

# 编译(FQBN 里的 CDCOnBoot=cdc 和 PSRAM=opi 都不能少);★ 两个参数都要给,见下面第 3 条坑
"$CLI" compile --fqbn "esp32:esp32:esp32s3:CDCOnBoot=cdc,PSRAM=opi" \
  --build-path "$CACHE" --output-dir "$OUT" "$SRC"
```

> **`PSRAM=opi` 是 2026-10-11 新增的，别省。** 芯片本来就有 8 MB PSRAM，但默认是关的。
> 不开它，**动图页**（点报文区进的那页）的全屏 sprite 要挤 153,600 B **连续**内部 RAM，
> 扫过一次 WiFi 之后必然失败 —— 表现就是"**点报文区进不了动图页**"。
> 配套的 `firmware/GNSS_Bench/build_opt.h`（一行 `-DCONFIG_SPIRAM_SUPPORT`）**别删**：
> `PSRAM=opi` 只加 `-DBOARD_HAS_PSRAM`，而 TFT_eSPI 判的是 `CONFIG_SPIRAM_SUPPORT`。

> ## ⚠️ 三条实测坑(踩过)
>
> **1. 构建目录绝对不能放在同步盘上。** 用 `--build-path "D:/<同步盘>/.../build"`
> 时,链接阶段会报一大片 `undefined reference`,连 `millis`、`app_main` 这些核心符号
> 都找不到 —— 是**同步盘把构建缓存搅坏了**,看着像代码坏了,极容易误判。
> 必须把 `--build-path` 指到本地盘(`%TEMP%`)。
>
> **2. ★ 只给 `--output-dir` 治不了根(2026-10-01 查清)。** `--output-dir` 只管**导出**最终产物;
> 而**中间缓存默认落在 sketch 目录下的 `build/`** —— 也就是 `firmware/GNSS_Bench/build/`,
> **约 21MB,直接长在同步盘上**。这正是本坑反复出现(09-30 一天删了两次)的**根因**。
> → **两个参数必须同时给**:`--build-path` 指 `%TEMP%\gnss-cache`。编译完 `ls` 一下
> `firmware/GNSS_Bench\`,确认**没有**多出 `build/`。
>
> **3. `--output-dir` 出来的产物不含 `boot_app0.bin`。** 从
> `firmware/GNSS_Bench/prebuilt/boot_app0.bin` 拷一份到输出目录再烧。

## 五、程序分段,按顺序读就是完整的数据流

| 段 | 在 .ino 里的位置 | 职责 | 你可以单独调什么 |
|---|---|---|---|
| **★ 配置区** | 文件最开头 | 引脚 / 波特率 / **所有判据阈值** / 屏布局 | **要改的东西几乎都集中在这一块** |
| **1 收** | `namespace gnss` | 只负责把 NMEA 行收进环形缓冲,不解析不判断 | `GNSS_BAUD`、`NMEA_POOL` |
| **2 解** | `namespace nmea` | 校验和 + 拆字段,提取星数 / HDOP / C/N0 / 经纬度 | 要加解析别的句子(如 RMC 取速度)在这里加 |
| **字模** | `namespace cnfont` | 32x32 中文状态词点阵,**自动生成,不用读** | 想改字样就跑 `scripts/gen_cnfont.py` |
| **3 判** | `namespace judge` | 四态判定、迟滞、冷启动宽限、注入、基准存储 | 阈值已经提到配置区了 |
| **灯** | `namespace led` | 板载 WS2812 与屏上色带同色同步 | 引脚 `LED_RGB_PIN`、亮度 `LED_BRIGHT`、驱动方式 `LED_USE_BUILTIN` |
| **温湿度** | `namespace sht` | SHT30-D(I2C),屏右下角 `T` / `RH`,串口 `t` 可随时验证 | 引脚 `PIN_SHT_SCL` / `PIN_SHT_SDA`、刷新周期(2 秒) |
| **4 显** | `namespace disp` | 状态带 / 报文窗 / 指标区三区绘制 | `SCR_*` 那几个布局常量 |
| **触摸** | `namespace touch` | XPT2046 校准 + 屏上点击(存基准 / 切注入) | `ENABLE_TOUCH` 开关、可点区边界 |
| **5 主循环** | 文件末尾 | `setup` / `loop` / 串口控制台 / 串口汇报 | 各任务的刷新节奏 |

### 控制方式(两条路并存)

**点屏**:

| 点哪 | 干什么 |
|---|---|
| 顶部状态色带(整块) | 把当前定位存为基准 |
| 中部报文窗 | 切进**第二界面「动图页」**(独占全屏,四张动图每秒刷新;页内**点任意处返回**) |
| 底部指标区 | 切换"注入偏移" |

屏上两处都有 `TAP HERE = ...` 的小字提示(报文窗那片不挂小字,点一下就知道能进第二界面)。

**串口**(Arduino IDE 串口监视器 115200,输单字符回车):

> **v1.5.10 变更**:① **删除 `l`(试灯)与 `p`(报文池原文打印)** —— 用户定;
> ② 指标区右侧多了个 **WiFi 图标**(翠绿=已连 / 深灰=未连);
> ③ 排针上那对 **RX/TX(GPIO44/43)** 成了与 C3 命令板的链路口
> (走 UART1 重映射,不占 ROM 的 UART0;协议见 `GNSS_Bench.ino` 的 `benchlink` 段)。
> C3 发来的命令与电脑敲键**走同一份分派** —— 屏上点 `STATUS` 和电脑敲 `s` 完全等效。

| 命令 | 作用 |
|---|---|
| `b` | 把当前定位坐标存为基准(**仅本次上电有效,开机清零** —— 故意不写 NVS,免得跨上电残留旧基准) |
| `c` | 清除基准 |
| `i` | 切换"注入偏移"(无基准时无效,会提示先发 `b`) |
| `s` | 立即打一行状态 |
| `t` | 立刻读一次温湿度(不等自动的 2 秒节拍,现场查接线用;读不到会打 `READ FAILED`) |
| `g` | **PPS 观测**:脉冲数 / 间隔 us / ppm / 折算日漂移。未定位时模块不出 PPS,读数为 0 属正常 |
| `1` | **模拟信源·正常**:凭空生成 GGA/RMC/GSV,9 星 / HDOP 1.1 / CN0≈40 → 绿带。不需要 GNSS 模块 |
| `2` | **模拟信源·信号差**:3 星 / HDOP 6.9 / CN0≈17 → 红带(信号异常档) |
| `3` | **模拟信源·坐标漂移**:与正常场景同指标,唯独坐标北移约 200m → 需先存过基准,偏移超 30m 触发红带(位置异常档) |
| `0` | 关闭模拟,交还真实模块(v1.5.4 起:开模拟期间真实报文不进池;关后 1~2 秒恢复真实值。**若基准是模拟坐标会持续红**——`c` 清基准或重 `b` 即回绿) |
| ~~`m`~~ | ~~**屏面镜像开关**(1Hz `@MIR` 状态行 + `@MSG` 报文转发,给电脑端演示面板用),默认开~~ ★ **v1.8.0 已删除**（`@MIR`/`@MSG` 整套去掉，电脑端面板 2026-10-17 也删了） |
| `d` | **切第二界面「动图页」**:独占全屏,四张动图(星空图 / 每星 C/N0 竖条 / 定位漂移散点 / 双星座趋势)每秒刷新。和「点报文区」完全等价;页内**点任意处返回**主界面 |
| `w` | **WiFi 存档(v1.5.6)**:子命令 `wadd <ssid> <密码>` / `wlist` / `wdel <n>` / `wconn [n]` / **`wscan`(v1.5.15)**(组号从 1 数)。最多 10 组,NVS 掉电不擦;**存满再存 = FIFO 覆盖最旧**。开机自动连第 1 组,连不上不卡主流程。<br>★ `wscan` = 给 C3 命令板当"扫描服务端"(异步扫周边热点,结果分条发给 C3)。**正常不用手敲** —— 在 C3 的 `WIFI / S3 / SCAN` 里点一下就会发过来 |
| `v` | **串口日志开关**:默认关(5 秒状态行 + 触摸坐标打印都不出)。调试时敲一下打开,再敲关闭 |
| `r` | 清除触摸校准值(重启后重新校准)。**清的是 S3 这台**;C3 命令板有它自己那套 |
| `?` | 帮助 |

`Serial` 每 5 秒还会自动打一行状态(星数、HDOP、C/N0、偏差、基准与注入开关),不开屏也能调。
**但这条默认是关的**(见上面 `v` 命令)—— 板子跑顺之后串口保持安静,想看时敲 `v` 打开。
你自己敲的命令(`s`/`b`/`i`/`t`/`g`…)永远有回应,不受该开关影响。

**调试顺序建议**:先把 `disp::begin()` 和 loop 里三次 `disp::draw*()` 调用注释掉,只留串口 —— 确认收到的星数、HDOP、C/N0 是真的;再开屏;最后开判据和注入。不要一次全接上。
第一次调试还可以把配置区 `ENABLE_TOUCH` 改成 `0`,跳过触摸初始化(那一步要你在屏上点四个十字,会在串口看到字的确认之前先挡住流程),等屏和串口都确认正常了再改回 `1`。

> **关于冷启动宽限(第 3 段里的一段专门逻辑)**
> 上电后如果立刻按判据算,前几秒必然"无定位",会当场报警 —— 现场看着像设备坏了。所以加了宽限:**从没定过位、且开机不到 90 秒**时,只提示"搜星中"(蓝带),不报警。一旦成功定位过,宽限立刻失效,后面该报就报。
> 另有一个诊断态:**一个字都没收到**时显示"等待数据"(蓝带)—— 那多半是接线或波特率问题,不是信号异常。

## 七、常见坑

| 现象 | 原因 | 处理 |
|---|---|---|
| **编译到最后一步报 `系统找不到指定的路径` / `exit status 1`** | 选中了残缺的那个内核(`arduino:esp32` 3.3.7),它的 `tools/` 下没有 `esptool`、`esp32-arduino-libs` | 换 `esp32:esp32` 那个。菜单里两个同名,靠编译输出里的 `FQBN:` 那行确认——必须是 `esp32:esp32:esp32s3` |
| **串口监视器一片空白,但屏上一切正常** | 数据线插在**原生 USB 口**,而 `USB CDC On Boot` 是默认的 `Disabled` → `Serial` 走的是 UART0(GPIO43/44),那个口上没接任何东西 | 工具菜单 → `USB CDC On Boot` → **Enabled**,重烧。(哪天换用板载 CH340 那个 UART 口,再设回 `Disabled`) |
| **屏上画面卡住不动(判据、灯、报文全停)** | 开着 `USB CDC On Boot` 但电脑上没开串口监视器,CDC 写操作**阻塞等主机来取数据** | 固件里已加 `Serial.setTxTimeoutMs(0)`,不会阻塞。若仍卡,看是不是自己往主循环里加了大量 `Serial.print` |
| 串口全是乱码 | 波特率不对 | ATGM336H 默认 9600;若改过,试 4800 / 38400 / 115200 |
| 一直收不到星 | 天线无源 / 放在室内深处 | 换有源天线;天线必须放到窗外或窗台 |
| 有报文但 quality 一直是 0 | 天线接触不良,或模块供电不足 | 检查 IPEX 座子;量一下模块 VCC 是否 ≥3.3V |
| 屏白屏 / 花屏 | TFT 驱动宏或引脚对不上 | 改 `User_Setup_GNSS_Bench.h`;先跑 TFT_eSPI 自带的示例确认屏能亮 |
| **屏上某个颜色不对(最典型:蓝色显成红色)** | 面板红蓝通道被换(本机 User_Setup 曾为 3.2 寸屏设过 `TFT_RGB_ORDER TFT_BGR`,2.4 寸屏不需要) | 串口发 `o` 当场验证;确认后把 User_Setup.h 里的 `TFT_RGB_ORDER` 设为对应值。若是黑显成白则发 `n`,确认后加 `#define TFT_INVERSION_ON` |
| **上电后屏全黑,但串口正常在打状态** | **背光(BLK)没供电** | 本项目 BLK 接 3V3。若你的 BLK 其实插在 GPIO7 上,则要在配置区把 `TFT_BL_ON_GPIO` 改成 `1` |
| **温湿度一直显示 `T --` / `RH --`** | SHT30 没接 / 接反 / 上拉缺失 | 串口发 `t` 看回显:打 `READ FAILED` 就是 I2C 不通。查 SCL=GPIO7、SDA=GPIO8 有没有接反、共地、模块是不是 3.3V 供电。**换了屏背光接法的话,这两个脚要一起改** |
| 屏亮但点屏没反应 | 触摸没校准,或校准值与屏幕方向不匹配 | 串口发 `r` 清掉校准值,重启重新点四个十字;确认没改过 `setRotation` |
| 点屏位置总是偏 | 校准值作废(换过屏 / 改过方向) | 同上,重新校准。校准值是和屏幕方向绑定的 |
| 编译报 `当前生效的 User_Setup 引脚不是台架接线` | User_Setup 没挂对,或挂的不是这一份 | 回第四节第 5 步。报错会列出应有的脚号(CLK12/MOSI11/MISO13/CS10/DC6/RES4) |
| 编译报 `触摸片选不是 GPIO9` | 同上,挂的是别的触摸配置 | 同上 |
| 编译报 `ENABLE_TOUCH=1,但 User_Setup 里没有 #define TOUCH_CS` | 两个触摸开关不一致 | User_Setup 里打开 `#define TOUCH_CS`,或把 `ENABLE_TOUCH` 改成 `0` |
| 星数在两个星座间跳 | 正常现象 | 代码里 GP / BD 已分桶,`VIEW` 取的是最后一句的值,略有跳动属正常 |
| 上电后一直蓝带"搜星中" | **正常**,冷启动宽限在起作用 | 等它定位。超过 90 秒还没转绿才需要查天线 |
| 一直蓝带"等待数据" | **一个字都没收到**,是接线 / 波特率问题,不是信号异常 | 查 TXD/RXD 有没有接反、共地、波特率 9600 |
| 编译报找不到 `TFT_eSPI.h` | 没装库,或没挂配置 | 库管理器装 TFT_eSPI;按 `User_Setup_GNSS_Bench.h` 头部三步挂配置 |
| 编译报 `'rgbLedWrite' was not declared` / `'neopixelWrite' was not declared` | 核心版本判定没走到(极少见的老核心或分支) | 把文件顶部 `LED_USE_BUILTIN` 改成 `0`,库管理器装 **Adafruit NeoPixel** |
| **板载灯完全不亮(第一嫌疑)** | **RGB 数据线出厂是断开的** —— 灯旁那对丝印 `RGB` 的小焊盘没短接 | 用锡把那对焊盘连上。表现是"程序烧录正常、屏也正常、就是灯不亮",先查这里 |
| 板载灯完全不亮(第二嫌疑) | 脚位不对(官方 v1.0 是 38;克隆板常见 38 / 21 / 47) | 串口发 `l` 挨个试,哪个亮就把配置区 `LED_RGB_PIN` 改成它 |
| 灯颜色反了(该红显绿) | 这颗灯的色序不是 GRB | 把 `led::writePix` 里的 `rgbLedWrite(pin, r, g, b)` 换成 `rgbLedWriteOrdered(pin, LED_COLOR_ORDER_RGB, r, g, b)` |
| 编译报重复定义 | 单文件版和分开版混放在同一文件夹 | 两套二选一,只留一套 |
| **链接阶段报一大片 `undefined reference`,连 `millis` / `app_main` 都找不到** | **构建目录放在百度同步盘上,缓存被同步搅坏** | `--build-path` 一律指本地盘(`%TEMP%`),**绝不要**指到 `D:\<同步盘>\...` |
| **`firmware/GNSS_Bench/build/` 反复自己冒出来(约 21MB,占同步盘)** | **`--output-dir` 只搬导出产物,中间缓存仍落在 sketch 目录** | 编译时**同时**给 `--build-path "%TEMP%\gnss-cache"`(2026-10-01) |
| `--output-dir` 编出来的目录里没有 `boot_app0.bin` | arduino-cli 默认不输出它 | 从 `firmware/GNSS_Bench/prebuilt/boot_app0.bin` 拷一份过去再烧 |
| **顶部能点、底部点不动;或触摸整体失灵** | **换了屏,但 NVS 里还是旧屏的触摸校准值**(y 量程差一倍,下半截坐标出界被判无效) | 串口发 `r` → 重启 → **重新点 4 个十字**。换屏后必做 |
| 屏上蓝红反了 / 屏干脆不亮 | TFT_eSPI 的 `User_Setup.h` 没挂对(常见:漏了 `TFT_RGB_ORDER TFT_BGR` 或 `USE_FSPI_PORT`) | 按第四节第 5 步挂对。色序/反显**没有串口命令**(2026-10-02 起 o/n 已删),改宏重烧一次 |
| **无定位时 HDOP 显示 25.5** | **模块自己的占位值**(`$GNGGA,,,,,,0,00,25.5,,,,,,*64`),不是固件问题 | 判据不受影响(`!fixValid` 先生效走蓝档)。是否隐藏成 `---` 待定 |
| 开机 `BASE` 是 `---` 不是 `SET` | **设计如此**:基准已改为会话制,开机清零 | 定位后按 `b`(或点色带)存;想恢复持久化就把 `saveBase`/`loadBase` 里的 NVS 调用加回来 |
| 串口刷屏、不想看日志 | 5 秒状态行与触摸坐标打印 | 敲 `v` 关闭(默认就是关的);命令应答不受影响 |
