# 设计规则总览 — GNSS 台架 v1.10.2 / C3 v1.2.5

> 用途：升级、换板、接手之前先把"现在为什么这么设计"读一遍。
> **每条规则都标了出处**（源码行号以 v1.10.2 为准，改版后会漂，看函数名/常量名更可靠）。
> 写法：**规则 → 为什么（不这么干会怎样） → 出处**。
>
> 这份文档不描述"功能有哪些"，只描述**约束**。功能清单见 `README-交接（笔记本继续）.md`。

# 一、系统边界：谁负责判定

| 角色 | 职责 | 不该做的事 |
|---|---|---|
| **S3 台架面板** | 收 GNSS、算完好性、**做全部判定**、存事件、显示 | 不做遥控、不做执行机构 |
| **C3 命令板** | 人机界面：发命令、看回执、搬事件日志 | **不重复实现判定**（否则两边口径分叉） |
| **电脑串口** | 排障 / 演示注入 | 不参与判定 |

**规则 1.1｜判定只有一个地方。** C3 上看到的"好不好"永远是 S3 算完发过来的字符串，C3 只负责显示。
**为什么**：一旦 C3 自己也判，两块板会出现"屏上绿、C3 上红"的场面，现场无法解释。
**出处**：`C3_CmdPad.ino` v1.2.x 注释；`evtr/evtd` 帧里的 `<col>/<word>` 都是 S3 现算现发。

**规则 1.2｜协议号（P2）与固件版本号（vX.Y.Z）是两件事。**
协议号只在**帧格式变了**的时候才动；固件版本号每版都动。
**为什么**：把两者混成一个号，会导致"小改一个显示也要两板同批烧"。
**出处**：`kProto = 2`（S3:5790 区 / C3:870）；`kVer`（S3:5933 / C3:1191）。校验 `tools/check_proto_sync.py`。

**规则 1.3｜协议号不一致只告警、不拒绝执行。**
**为什么**：现场烧错一版还能用，不至于整台设备瘫掉；但屏上必须点名，不能装作没事。
**出处**：`link proto ok (both P2)` / 不一致时 `[bench] link proto MISMATCH`。

# 二、接线：颜色不是审美，是排线的物理约束

## 2.1 硬前提

**规则 2.1｜标准彩排线是 10 色固定色序，且首尾相接。**
```
棕(1) 红(2) 橙(3) 黄(4) 绿(5) 蓝(6) 紫(7) 灰(8) 白(9) 黑(10) →（回到棕）
```
**所以配色不是"想给谁给谁"，而是先看排线、再把用途塞进已有段落。**
**出处**：`docs/接线表-双板与彩色杜邦线配色.md` §1。

**规则 2.2｜用途按"排线段"切，不按"模块"切。**

| 段 | 颜色 | 用途 |
|---|---|---|
| 电源 | 红(2) | +3.3V |
| 信号 | 橙(3) 黄(4) 绿(5) 蓝(6) 紫(7) 灰(8) | 连续 6 根，按模块撕 |
| 链路/地 | 白(9) 黑(10) 棕(1) | 黑=全部 GND；白+棕=链路两根；黑夹中间 |

**规则 2.3｜"地夹在两信号中间"只有一种物理实现：白-黑-棕。**
**为什么**：黑在排线上只与白、棕相邻。想做屏蔽，没有第二种选法。
**代价（必须承认）**：红(2) 与黑(10) 在排线两端 ⇒ **"电源+地成组"物理上做不到**，别硬凑。

**规则 2.4｜绿/蓝表示方向，不表示模块。**
本机 **TX = 绿**、**RX = 蓝**。同一个模块上"发给它的走绿、它发来的走蓝"。
**为什么**：接错方向是最常见的故障，用颜色把方向固化，低头一看就知道接反了没。

**规则 2.5｜屏 SPI 三根主干必须是 黄/绿/蓝（排线相邻 3 根）。**
**为什么**：撕一小段正好够，而且**时钟（黄）夹在两根数据线中间**，20 MHz 下更稳。

**规则 2.6｜链路的交叉关系写死在颜色里：白=C3 RX↔S3 TX，棕=C3 TX↔S3 RX。**
⚠ 接成"同名对同名" ⇒ 两侧 RX 互连 ⇒ **两侧都不通，现象像"线全断"**，极具欺骗性。

**规则 2.7｜别照板厂丝印接 C3。**
C3 SuperMini 丝印把 IO4 标成 SCK、IO5 标成 MISO…那是"建议命名"，**照它接必黑屏**（背光是硬接 3.3V 的，所以"背光亮"根本不代表接线对）。

## 2.2 已经踩过的坑（写进规则里防止再踩）

| 坑 | 真相 | 教训 |
|---|---|---|
| "S3 的 GPIO43/44 被 CP2102N 顶着、做不了外部输入" | 线插在**松掉的面包板孔**上 | **不可靠的物理层会产出长得很像"器件缺陷"的证据** |
| "C3 的 20/21 做不通" | 同上，改焊线当场双向通 | 换线优先焊，不依赖插孔 |
| 早期链路配色 蓝/绿/黑 | 在排线上隔了紫灰白三根，**物理上撕不到一起** | 配色前先摊开排线看色序 |

# 三、版面几何：所有尺寸都是算术结果，不是感觉

## 3.1 主界面三段式（240×320 竖屏）

```
y   0..239   星空图区 240×240 —— 圆盘 R87 + 外圈 2px 状态光环 + 四角 HUD 块 92×24
y 240..273   按键条   240×34  —— BASE / CLR-BS / CHARTS / LOG，每键 60×34
y 274..319   数据条   240×46  —— 左状态词(FONT4) + 右 HPL/CN0/SAT 三行
```

**规则 3.1｜按键条 + 数据条必须正好铺满 240..319。**
`static_assert(BTN_Y + BTN_H + DATA_H == SCR_H)`（:592）
**为什么**：这两个数一改，底部 sprite 尺寸、报文窗 8 行、`BOT_Y` 全跟着动。用断言钉死，改一个数就编不过。

**规则 3.2｜按键条四等分。** `static_assert(BTN_W * 4 == SCR_W)`（:633）

**规则 3.3｜星空图半径有算术上限，不是"再大一圈"。**
四角块最内角 (94,26) 到圆心 (120,120) 距离 = √(26²+94²) = **97.53** ⇒ 环外沿最多 97。
现取 91，**留 6.5px 余量**。`static_assert(...)`（:626）在编译期拦住"光环压到四角块"。

**规则 3.4｜圆盘与光环之间必须留 2px 页底色。**
`static_assert(R_RING_IN - R_STAR >= 3)`（:631）
**为什么**：光环要"悬浮"在圆外。贴在一起就成了"圆盘边比较粗"，语义丢了。

**规则 3.5｜四角块高度必须装得下两行 8px 字。**
`static_assert(HUD_H >= HUD_LH + 8 + 2)`（:616）

## 3.2 其他页

| 页 | 关键约束 |
|---|---|
| 报文窗 | 8 行 × 10px = 80，占 y240..319 整块；38 字符 = 228px |
| WiFi 卡 | 176×60，居中 x32、y90；三行 10/26/42，末行底 50，上下各留 10 |
| BACK 键 | 64×24，右对齐 `SCR_W-6-64 = 170`，y=2 |
| CHARTS 四卡 | BAR 28..91 / TRD 94..157 / INT 160..235 / DET 238..316，**缝 2px**，四条 `static_assert` 锁间距（:3099-3100） |

**规则 3.6｜每加一条 `static_assert`，等于把这个尺寸从"约定"变成"编译期法律"。**
现有的 13 条断言覆盖：引脚归属、按键条铺满、四角块装字、光环不压块、环缝、WiFi 卡三行、卡片间距、BaseBlob 布局、参数表项数。

# 四、视觉纪律

**规则 4.1｜块一律不描边。**
**为什么**：块贴块再各描一圈边，四条线挨在一起像"框套框"，观感发脏。
**做法**：先铺一圈 **2px 页底色当"缝"**，再填块底色。这样它压在星空圆盘上也能看出是一张卡。
**出处**：:699、:2567、:2672、:2784、:3426、:4045、:5824-5832。

**规则 4.2｜边框只留给危险态。**
参照 C3 的规律：告警弹窗、删除键才允许有描边。常态元素一个都不许描。

**规则 4.3｜状态语义靠"底色 + 词 + 光环"三重承载，不靠边框。**
v1.7.1 把 BASE 的两态从**描边色**改成**底色**承载——因为描边被整体取消了。

**规则 4.4｜占位串与真值等宽。**
**为什么**：串变短会在定宽块里留残影。时钟条、坐标条都遵守这条。

**规则 4.5｜色彩语义（状态 → 颜色）**

| 状态词 | 颜色 | RGB565 |
|---|---|---|
| INTEG OK | 绿 | — |
| SEARCH / NO-DATA | 灰 | `#7A8794` |
| DEGRADED | 黄 | — |
| SIG-BAD | 橙 | — |
| POS-BAD | 红 | `0xFA69` `#FF4D4D` |
| LOST | 红**闪**（300 ms 灭相 = 页底色） | 同上 |
| HPL-HIGH | 紫 | `0xA45F` |
| DRIFT | 琥珀 | `0xFD80` |

**规则 4.6｜红闪只给 LOST，别滥用。**
**为什么**：闪是"最高级别告警"的语义。POS-BAD 是稳态异常，用它会把 LOST 降级。

# 五、防闪屏：这一块的规则最硬

## 5.1 原理

**规则 5.1｜"直接画"永远会闪，sprite 才是唯一画法。**
**为什么**：直接画一次重绘是一段几十毫秒的"亮度脉冲"，节拍正好踩在人眼最敏感那档。
sprite 在内存里合成完再**一次性推屏**，亮度全程恒定 ⇒ 闪感消失。
**出处**：:670-683（报文窗段）、:3037。

**规则 5.2｜合成期间屏幕一个像素都不动。**
⇒ 绝无撕裂、无闪烁。和报文窗同一个原理。

**规则 5.3｜"内容没变就一个像素都不动"（去重缓存）。**
`static PaintCache` 记"上次画出的内容"，内容相同直接 return。
**为什么**：1 Hz 刷新下大部分字段没变，每帧全重画等于每秒制造一次闪。
**出处**：:2357-2381、`:3011 resetPaintCaches()`。

**规则 5.4｜加新去重键必须同步加进 `resetPaintCaches()`。**
**为什么**：漏一个 ⇒ 换页后旧值被当成"没变"⇒ 那一格永远不更新（症状：切页后某个数字卡住不动）。

**规则 5.5｜页面/选择变化必须 `markDirty()`。**
**为什么**：不置脏 ⇒ 下一次重绘被去重逻辑吃掉 ⇒ 屏幕停在旧页面。

## 5.2 分带（无 PSRAM 的教训）

**规则 5.6｜整页原子重绘必须按内容切带，边界落在文字行之间。**
**为什么**：C3 没有 PSRAM，整屏 sprite 分配不起；直画又会"画一半被看见"。
**做法**：每带整带合成、一次 push、立即释放；分配失败降级直画。
**出处**：C3 v1.2.2 的搬运页。

**规则 5.7｜整块 sprite 绘制的第一件事是**填页底色**。**
**为什么**：漏填 = 上次内容残留在边角（残影）。

**规则 5.8｜绘制粒度判据：落笔像素量 × 8 ÷ SPI 频率 > 16.7 ms 就见闪。**
超过就切带或改成"只重画变化的那几格"。
**出处**：`skills/fixed-width-cell-redraw`。

## 5.3 最小重绘的两种手法

| 手法 | 适用 | 例子 |
|---|---|---|
| 定宽字符格 | 每拍都在变的数字/时间 | 时钟、坐标、计数器——只擦画真的变了的格子 |
| 整圈/整块重绘 | 形状类 | 状态光环只重画那 2 圈（≈1056 px），稳态 0 次/秒，LOST 时 300 ms 一次 |

**规则 5.9｜旧写法"每 300 ms 重铺 240×100 色带"= 24,000 px，现已省 >95%。**
**为什么**：省的不只是 SPI，还有"大面积变化"带来的视觉疲劳。

# 六、交互规则

## 6.1 时间常量（全部单点定义）

| 常量 | 值 | 含义 |
|---|---|---|
| `kPressure` | 600 | 按下判定压力阈值 |
| `kDebounce` | 350 ms | 两次有效点击最小间隔 |
| `kTouchWarm` | 2000 ms | 上电头 2 秒不认触摸（防幽灵点击） |
| `kLongPressMs` | 800 ms | 数据条长按 → 切报文窗 |
| `kTuneHoldMs` | 1500 ms | CHARTS 长按 → 进参数页 |
| `kClearHoldMs` | 5000 ms | CLR-BS 长按 → 清基准（满 5 s 当场生效） |
| `kSwipePx` | 40 px | 日志页翻页判定（竖直位移） |
| `kCardMs` | 4000 ms | WiFi 卡自动收 |

**规则 6.1｜同一个时间常数只许有一个真源。**
历史教训：`TH_HOLD_MS` 与 `kHplHoldMs` 曾同时存在同一个"迟滞 5 秒"，屏上改一处、另一处不动——**代码读起来完全正常**，只有现场"怎么改了不生效"才暴露。现已合并成 `tune::holdMs()`。

**规则 6.2｜控件的选型先算再选。**
HDOP 40 档 ÷ 220 px = 5.5 px/档，触摸层 40 px 的横向滑动判定还会把横拖吃掉 ⇒ **拖动块不可行，用四键**。
步进键的标签必须显示**实际增量**（HDOP 是 ±0.1 / ±0.5），不写"±1 步"。

**规则 6.3｜长按必须给"进度可见"的反馈。**
按键底部的绿条逐格长满 → 到位才执行。
**为什么**：5 秒的操作如果没有任何反馈，用户会以为没按上，然后松手重按。
⚠ 这类交互（长按 + 进度条）业界已有大量先例，**没有新颖性可言**，但**必须有**。

## 6.2 触摸状态机的坑

**规则 6.4｜"刚按下"的判据不能复用"一直按着"的状态量。**
真缺陷：原判据 `!wasDown`，而 `wasDown` **初值是 true**（上电 2 s 闸）。开机 splash 阻塞 7 s，主循环第一次 `poll()` 时它还是 true ⇒ **整次点击被静默丢弃**——串口有回显、屏无反应、不报错。
修法：改用独立的 `!downSeen`。
**通用教训：凡"第一次操作无效"，先去看那个状态量的初值。**

**规则 6.5｜长按阈值与点击阈值必须互斥且可切换。**
数据条：短按无动作 / 长按 800 ms 切报文窗。
CHARTS：短按切第二界面 / 长按 1.5 s 进参数页。
**一旦长按触发，必须把点击路径堵上**（`tuneFired` / `clrFired` 标志）。

# 七、状态机：六档状态词

## 7.1 判据拆两条

```cpp
overLim = off > tune::posLim();        // 当场可量的事实
driftOn = !overLim && integ::slowOn(); // 趋势判断
```

| 状态词 | 触发 | 语义 | 颜色 |
|---|---|---|---|
| `INTEG OK` | 一切正常 | 结论可信 | 绿 |
| `DRIFT` | CUSUM 超限但未越限 | 趋势在漂 | 琥珀 |
| `HPL-HIGH` | 保护级超告警限 | 结论不可信 | 紫 |
| `POS-BAD` | 偏差超 POS LIM | 当场可量的越界 | 红 |
| `SIG-BAD` | 星少/HDOP 差/无定位 | 信号本身不行 | 橙 |
| `DEGRADED` | 一般质量下降 | 还能用 | 黄 |
| `SEARCH` | 有数据未定位 | 冷启动正常态 | 灰 |
| `NO-DATA` | 一个字都没收到 | — | 灰 |
| `LOST` | 定过位又丢 | 真丢了 | 红闪 |

**规则 7.1｜距离优先。**
`POS-BAD` 压过 `DRIFT`：既然已经越线，就不必再讲"趋势"。

**规则 7.2｜冷启动不许报红。**
"从未定位"= `NO-DATA`（灰，正常等星）；"定过位又丢"= `LOST`（红闪，真丢了）。
**为什么**：按 Level 取色会让"刚开机还没定位"红屏闪，看着像设备坏了。
冷启动给 90 s 宽限（`TH_COLDSTART_MS`）。

**规则 7.3｜状态词枚举**新增只能追加在末尾。**
`PH_DRIFT` 必须排在 `PH_HPLHIGH` 之后（=10），**不能插队**。
**为什么**：`type` 会被写进 NVS 的事件日志，插队会让历史记录全部错位。

**规则 7.4｜迟滞：异常连续 5 s 才报，正常连续 8 s 才解除。**
**为什么**：不迟滞会在阈值附近疯狂跳变，屏幕和日志都被刷爆。

# 八、三个算法

## 8.1 保护级 HPL

```
HPL = kHplK · HDOP · σ_UERE
σ_UERE 由 C/N0 反推：σ = kSigRefM × 10^(-(CN0 - kCn0Ref)/20)
kHplK = 5.33    kSigRefM = 0.6 m @ 45 dB-Hz
```

**规则 8.1｜σ 取"最强前 `satsUsed` 颗"，不许用 GSA 的 PRN 槽。**
**为什么**：GSA 有 12 个 PRN 槽、多句 `$GNGSA`、句名一律 `GN`、PRN 跨星座重号 ⇒ 实测 σ=8.7 m、HPL 常年 40 m，毫无意义。

**规则 8.2｜kHplK 与 σ 模型是**标定项**，锁死，不进参数页。**
**为什么**：改它们等于改"我这台设备的尺子"，会让 `tools/cusum_replay.py` 那份离线证据失效。
判据一句话：**改了这个数，我手里那份验证还成立吗？** 成立才允许上屏。

**规则 8.3｜AL（告警限）可以现场配。**
航空界本来就支持 LPV-200 35 m / APV-I 40 m ⇒ "AL 可调"是专业做法，不是把标定改松。

## 8.2 CUSUM 漂移检测

```
一阶低通 α=0.05 (τ≈20 s) → 压逐拍噪声
慢基线 μ α=0.003 (τ≈5.5 min) → "平时在哪儿"
统计量 S = max(0, S + dev - 1.0)      // 1 m 以内不累积
判据 S > 20 (m·s) && 偏离 > 8 m       // 绝对闸
预热 90 s：只建 μ，统计量锁 0
```

**规则 8.4｜基线建立那一刻的输入必须可靠，否则要有**明说的预热期**。**
两次踩坑：① 拿 0 当基线（恒定偏差被当成漂移）；② 拿"进入那一拍的 off"当初值，而那一拍在开机时不可靠 ⇒ μ 从 0 爬 5 分钟，**一开机就在"漂"**。

**规则 8.5｜换基准 / 换尺子必须 `resetBaseline()`。**
**为什么**：不重置的后果是**漏报**（μ 记着旧的 200 m，dev 恒负，统计量永远压 0），不是误报。

**规则 8.6｜CUSUM 的真实定位是"第二道闸"，不是提前量。**
离线回放（0.02~0.4 m/s 斜坡）结论：**8 m 绝对闸先到，CUSUM 再确认 0 秒**。
⇒ 任何场合都不许说"提前发现"。**离线回放推翻了设计意图时，改口径、别改参数。**

## 8.3 多径检测

```
按 C/N0–仰角模板预测残差
RLS 在线拟合（遗忘因子固定）
残差 > kMpThrDb (10 dB) 计一次可疑
```

**规则 8.7｜多径阈值只告警，不参与 bad 判据。**
**为什么**：多径在城市里太常见，把它算进"位置异常"会天天误报。

# 九、基准与参数：可调 vs 锁死的分界线

## 9.1 分界线

> **可调 = "我认什么算异常"；锁死 = "我怎么算出这个异常"。**

| 可调（`namespace tune`，NVS `gnstune`） | 锁死（编译期常量） |
|---|---|
| POS LIM 30 m | kHplK = 5.33 |
| HPL LIM 30 m | σ(C/N0) 0.6 m @ 45 dB-Hz |
| HDOP MAX 2.0 | CUSUM α / μA / k / H |
| SAT MIN 6 | 多径 RLS 遗忘因子 |
| CN0 MIN 25 dB-Hz | 事件池容量 500 |
| MP THR 10 dB | 报文窗行高 10px |
| HOLD 5 s / RECOVER 8 s | |

**规则 9.1｜八项默认值 = v1.9.0 的编译期常量，一个都没改。**
上屏只是"允许改"，不是"改了默认"。

**规则 9.2｜改完下一次 1 Hz 拍就生效，不重启。**
例外：`HDOP MAX` / `SAT MIN` 只在"按 BASE"时被读，**不追溯**已存基准。

**规则 9.3｜写 flash 只在退出编辑页 / 回主界面时 `commit()`。**
**为什么**：每按一下步进键就写 NVS，闪存寿命和响应速度都受不了。

## 9.2 基准（BASE）

**规则 9.4｜准入条件就是精度上限。**
`fixValid && sat ≥ satMin && hdop ≤ hdopMax && 数据新鲜 < 3 s` 才放行；
再 1 Hz 采 10 s，**样本 ≥8、极差 ≤25 m** 才写**均值**。
**为什么**：只校验"有没有"不校验"准不准"，等于把随机误差永久固化。
历史事故：`saveBase` 只查 `fixValid` ⇒ 坏基准进 NVS ⇒ "设备永久漂移 200 m、重启也甩不掉"，症状长得像别的部件坏。

**规则 9.5｜三个入口必须走同一个函数** `judge::requestBase()`。
（主界面 BASE 键 / C3 SET BASE / 串口 `b`）

# 十、事件日志

| 项 | 值 |
|---|---|
| 容量 | 500 条环形池 |
| 防抖 | 新状态连续保持 15 s 才落一条 |
| 落盘 | NVS，**`seq` 必须与记录一起 `putUInt`** |
| 记录内容 | `type`（状态词枚举）、`t0`、`t1`、当时 `off` |

**规则 10.1｜任何状态词变化记一条，`t0..t1` = 该状态持续区间。**

**规则 10.2｜记录写对、索引没写 = 全丢。**
存 N 条就必须存计数/序号，并按它循环读。`seq` 曾漏写过一次。

**规则 10.3｜改"记录频率"必须同时算"覆盖时长"。**
1 条/分钟 × 100 条 = 1.7 小时，差一个数量级。现在的 500 条 + 15 s 防抖 ≈ 2 小时满池。

**规则 10.4｜诊断别急着加命令。**
NVS 命名空间名与键名都是**明文**，`esptool read_flash <偏移> <大小>` 整片 dump 后搜键名，几分钟出结论。

# 十一、双板链路

| 项 | 值 |
|---|---|
| 物理 | UART 交叉：C3 GPIO20(RX)↔S3 GPIO43(TX)，C3 GPIO21(TX)↔S3 GPIO44(RX) |
| 波特率 | 115200 |
| 协议 | P2，行文本帧，`@k`/`@s` 前缀 |
| 心跳 | C3 发 `@k ping P2`，S3 回 `@s ok proto P2` |
| 单键白名单 | **8 个**：`b c d v s g t r` |

**规则 11.1｜`k`（演示注入）不进链路白名单。**
**为什么**：只有电脑 USB 串口能敲，C3 发不进来。演示注入是"上帝视角"，不该暴露给现场设备。

**规则 11.2｜`p` / `k` 都是电脑串口命令，故意不进链路。**
白名单校验器 `tools/check_link_whitelist.py` 会核对条目数（8）与逐字符。

**规则 11.3｜每次改固件"所有命令敲一遍"。**
**为什么**：varargs/printf 没有编译期检查，改坏一处只在运行时静默出错。`check_printf_args.py` 兜底（现在 363 处）。

# 十二、C3 命令板的规则

## 12.1 结构

```
一级菜单 4 组：BASE / VIEW / SYSTEM / WIFI
  BASE   → SET BASE / CLEAR BASE      ← 内部数组仍名 kLv2_JUDGE（符号名不上屏，改名只增 diff）
  VIEW   → CHARTS / LOG
  SYSTEM → STATUS / PPS / TEMP-RH / TOUCH
  WIFI   → S3 / C3（各自 SCAN / ADD / DEL [/ PUSH]）
```

**规则 12.1｜内部数组名可以留旧，显示名必须与人脑一致。**
v1.2.5 只改了显示名 JUDGE→BASE，数组名不动。

**规则 12.2｜C3 不实现判定，只搬。**
事件日志搬运帧：`evth/evts/evtr/evtd/evtg`，颜色由 S3 给（`statusColor565(type)`），**只看类型**。
历史坑：v1.2.0 发的是"行色"（闭环=绿），S3 详情页大字却是状态色 ⇒ 两屏色差。

## 12.2 触摸/键盘

| 常量 | 值 |
|---|---|
| `kPressure` | 600 |
| `kDebounce` | 350 ms |
| `kTouchWarm` | 2000 ms |
| WiFi 台账 | 10 组，FIFO 淘汰最旧 |

**规则 12.3｜"连上才存"。**
`wadd` = 拿到有效 IP 才写 NVS；连不上一个字不存。
**为什么**：存了连不上的热点，下次开机会按顺序挨个试，白白拖慢启动。

**规则 12.4｜键盘是全屏自绘，只展示不提交时不会连网。**
`k add c3` 开键盘；不调 `kbFeed` 就不连网、不写台账；`t` 在键盘开着时只取消键盘。

# 十三、验证体系：五件套哨兵

| 哨兵 | 管什么 |
|---|---|
`tools/check_proto_sync.py` | 两板协议号一致
`tools/check_link_whitelist.py` | 白名单 8 个 + 逐字符 + 菜单表条目数
`tools/check_printf_args.py` | printf 格式串与实参数量
`tools/check_wifi10_sync.py` | WiFi 10 组函数无分叉
`tools/check_tft_fonts.py` | TFT 字库 1·2·4 = 15·8·3

**规则 13.1｜凡是"必须与别处一致"的字符串/表，一律脚本化校验，禁手抄。**
**为什么**：错误形态是**静默失灵**——白名单漏一个字符 = 菜单项永远不执行，不报错。

**规则 13.2｜验证脚本首次报 FAIL，先怀疑脚本。**
哨兵从不报警也要怀疑它死了 ⇒ **反向验证：故意改坏一处，看它是否拦得住。**

**规则 13.3｜"代码没问题但屏上没东西"要查库级编译开关。**
TFT_eSPI 的 `LOAD_FONTx` 在 `Arduino/libraries/.../User_Setups/*.h`，**项目目录零痕迹**。
缺字库 = 编译过、不崩、无警告、一个像素不画。
⚠ 库配置改动必须备份进项目根 `User_Setup_C3_CmdPad.h` + 脚本校验。

**规则 13.4｜改界面文字不必先烧板子。**
字符串常量原样进 `.rodata` ⇒ `grep -c <旧词> <bin>` 即判据：0 次 = 改干净；非 0 = 还有第二处硬编码。

# 十四、元规则（从事故里提炼的，比上面所有条都重要）

1. **凡"必须与别处一致"的表，脚本化校验，禁手抄。**
2. **验证脚本首次 FAIL，先怀疑脚本；哨兵从不报警也要怀疑它死了。**
3. **"两边都失败"先往外看**（共同的对端/环境），再怀疑个体。
4. **硬件先量物理层**（通断/短路/电压），面包板+杜邦线是已知不可靠层。
5. **历史结论也要复核**：文档写"某脚做不了"时，先问"当时怎么连的线"。
6. **列表型持久存储：记录写对、索引没写 = 全丢。**
7. **改记录频率必须同时算覆盖时长。**
8. **会被写进 flash 的参考量，入口的准入条件就是它的精度上限。**
9. **检测器的"基线初值"比公式更容易错。**
10. **离线回放可能推翻设计意图 —— 这时改口径、别改参数。**
11. **一个量只许有一个真源，尤其是时间常数。**
12. **每加一个独占全屏 sprite 的页面，必须按四条路径逐个点名补 release**（漏的那条不报错，只在下次分配时静默失败）。
13. **控件选型先算再选，别按直觉。**
14. **开机后第一次操作无效，先去看那个状态量的初值。**
